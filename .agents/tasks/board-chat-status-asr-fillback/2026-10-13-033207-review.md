# Chat 三槽状态刷新与 ASR 可编辑回填

本次改动修复了板端非当前 Chat 状态不重绘的问题，并在板连接和 Crew WebSocket 重连时重新投影三槽状态。ASR 与 Macro 改为写入 Kiro Crew 实时 composer，不再进入 REST 草稿或自动提交。K5 和板载编辑操作也作用于同一个 composer，用户可以修改识别结果后再提交。验证结果与 FEAT findings 一致，未发现阻塞问题。

Watch for: 无阻塞问题；硬件视觉刷新和 Windows 按键注入仍需板卡与 Kiro Crew 端到端确认，FEAT findings 已记录这一限制。

**Verdict**: APPROVED

## High-level view

固件对当前槽位立即重绘，对非当前槽位设置延迟重绘标志，由主循环在音频保护期结束后刷新包含三个状态颜色的侧栏。

Companion 在每次板连接后重放 Chat A/B/C。没有缓存状态的槽位会收到显式 `unbound` 帧；Crew WebSocket 新连接会重置快照去重，确保首个完整 `slots` 帧重新投影。

ASR、Macro、K5 和板载 composer 编辑事件不再被 REST 路由消费。识别文本通过 `Compose` 写入当前可见 composer 且不发送，编辑动作修改同一输入框，K5 通过 Enter 提交。

## 三槽侧栏刷新与重连投影

`display` 处理为非当前槽位设置 `s_lcd_redraw_pending`，解决侧栏颜色依赖槽位切换才更新的问题。当前槽位仍即时重绘，主循环沿用现有音频忙碌和 LCD 保护条件消费延迟标志。

`connect_device` 固定生成三个状态帧，缓存缺失时发送 `state="unbound"` 与空文本，从而覆盖固件跨连接保留的旧颜色。Crew WebSocket 连接成功时清空 `crew_api_slots` 去重快照，使内容相同的首个完整快照仍进入 `apply_status`。

## 实时 composer 的输入、编辑与提交闭环

`route_board_via_crew_api` 不消费 ASR、Macro、K5 和 Nav 事件。非空识别文本由 `ControlAction::Compose` 聚焦 Kiro Crew 并输入文字，没有 Enter 或 REST 请求；空识别结果仍映射为 `None`。

短左键、长左键和长上键分别操作 Backspace、持续 Ctrl+Backspace、Ctrl+A 后 Backspace，K5 Down/Long 操作 Enter。输入、修改和提交因此作用于同一个可见 composer。K1-K3 的 API 稳定槽位选择和可选 Alt+N 跳转保持不变。
